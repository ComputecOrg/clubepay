## Affected Pages/Routes
- `/[slug]` — Landing page do clube (SSR, público). Testar: renderização com dados reais, SEO meta tags, social proof counter, endereço visível, CTA de assinatura.
- `/dashboard` — Dashboard do dono (auth). Testar: stats (MRR, assinantes, adimplência), CRUD de planos, botão "Validar uso", banner de upgrade free→pro.
- `/validar/[slug]` — Validação de uso (subscriber auth). Testar: QR scan do balcão, busca manual, validação com limites diário/mensal, multi-plano selector.
- `/meu-plano` — Página do assinante (auth). Testar: ver plano, usos restantes, próxima cobrança, cancelar, link de indicação.
- `/api/psp/webhook` — Webhook do PSP. Testar: HMAC validation, payment confirmed/failed, idempotência, unknown subscription.
- `/api/cron/reconcile` — Cron de reconciliação. Testar: sync pagamentos pendentes, dunning grace expirado, PSP API down.

## Key Interactions to Verify
- Assinante escaneia QR do balcão → valida uso → vê confirmação com contagem atualizada
- Dono cria plano → vê landing page gerada automaticamente
- Assinante assina → autoriza Pix → recebe confirmação
- Assinante indica amigo → amigo assina → ambos recebem desconto
- Assinante cancela → acesso continua até fim do período

## Edge Cases
- Double-click no "Assinar agora" na landing page
- Assinante tenta validar uso além do limite diário/mensal
- Assinante com 2+ planos no mesmo negócio → selector
- Dono atinge 15 assinantes no free → novas assinaturas bloqueadas
- Webhook do PSP não chega → cron reconcilia no dia seguinte
- Assinante tenta usar plano cancelado/expirado
- Self-referral (mesmo email tenta indicar a si mesmo)

## Critical Paths
- Checkout completo: landing page → signup → PSP Pix Automático → webhook confirma → subscription ativa
- Validação de uso: QR scan → auth check → limit check → usage record → confirmação
- Dunning flow: payment fails → 3 dias grace → blocked → pagamento chega → reativa
- Cancelamento: subscriber cancela → PSP revocation → acesso até period_end
